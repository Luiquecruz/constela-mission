# Codemods, Typegen and Migrating Synchronous Request APIs

Migrating a large Next.js codebase from synchronous request APIs (`cookies().get(...)`, `params.slug`) to asynchronous Promises (`(await cookies()).get(...)`, `(await params).slug`) across hundreds of routes and layouts does not need to be done by hand. Next.js provides automated AST codemods (`@next/codemod`) and static route type generation (`next typegen`) to automate the transition and enforce compile-time safety.

## Automating Migration with `next-async-request-api`

The official `next-async-request-api` codemod scans your `app/` directory and transforms synchronous usages of `params`, `searchParams`, `cookies()`, `headers()`, and `draftMode()`:

```bash
npx @next/codemod@canary next-async-request-api .
```

### How the Codemod Transforms Server vs. Client Components

1. **Server Components, Route Handlers, and `generateMetadata`**: The codemod adds the `async` keyword to the component or function declaration, wraps `params` and `searchParams` property types in `Promise<...>`, and inserts `await` before `params`, `searchParams`, `cookies()`, `headers()`, and `draftMode()`.

```tsx
// Before codemod
import { cookies } from 'next/headers';

export default function SettingsPage({ params }: { params: { org: string } }) {
  const theme = cookies().get('theme')?.value;
  return <div>{params.org} - {theme}</div>;
}

// After codemod
import { cookies } from 'next/headers';

export default async function SettingsPage(
  props: { params: Promise<{ org: string }> }
) {
  const params = await props.params;
  const theme = (await cookies()).get('theme')?.value;
  return <div>{params.org} - {theme}</div>;
}
```

2. **Client Components (`'use client'`)**: Because Client Components cannot be `async`, the codemod imports `use` from `'react'` and unwraps `props.params` and `props.searchParams` via `use(props.params)`.

3. **Un-migratable Synchronous Helpers**: If `cookies()` or `headers()` is called inside a regular synchronous utility function that cannot automatically be converted to `async` without breaking all of its callers, the codemod inserts a diagnostic comment (`/* @next-codemod-error ... */`) and temporarily casts the return type to `UnsafeUnwrappedCookies` or `UnsafeUnwrappedHeaders` so you can refactor the call chain into an `async` function deliberately.

## Compile-Time Route Types with `next typegen`

Manually writing `{ params: Promise<{ tenant: string; id: string }> }` for every page and layout is repetitive and error-prone—if you rename a folder from `[id]` to `[projectId]`, hand-written types drift out of sync.

Running `npx next typegen` generates global helper types (`PageProps`, `LayoutProps`, and `RouteContext`) directly from your filesystem folder structure without running a full build:

```tsx
// app/[tenant]/projects/[projectId]/page.tsx
// PageProps<'/[tenant]/projects/[projectId]'> is generated by `npx next typegen`
export default async function ProjectPage(
  props: PageProps<'/[tenant]/projects/[projectId]'>
) {
  // TypeScript knows `params` is Promise<{ tenant: string; projectId: string }>
  const { tenant, projectId } = await props.params;
  return <h1>{tenant} / {projectId}</h1>;
}
```

Integrating `npx next typegen && tsc --noEmit` into your CI pipeline guarantees that every page and layout awaits `params` and `searchParams` with the exact dynamic segment names defined on disk.

## Common Pitfalls

- **Leaving `UnsafeUnwrappedCookies` casts in production code**: Codemod fallback casts (`as unknown as UnsafeUnwrappedCookies`) exist only to pinpoint synchronous helpers that need manual refactoring into `async` functions. Leaving them in place will fail at runtime once synchronous access is removed.
- **Hand-typing `params` as a plain object instead of `Promise<T>`**: Typing `{ params: { slug: string } }` compiles when using `await params` in TypeScript (since `await` accepts non-Promises), but misleads maintainers and breaks when passed to `React.use(params)`. Always type `params` as `Promise<...>` or use generated `PageProps` / `LayoutProps`.
- **Forgetting to run `next typegen` before `tsc --noEmit` in CI**: Because `.next/types` is git-ignored, running `tsc --noEmit` on a fresh CI checkout without running `npx next typegen` first will fail to resolve `PageProps` and `LayoutProps`.

## When to choose it

- **Use `npx @next/codemod next-async-request-api`** whenever upgrading existing App Router routes, layouts, or metadata functions from synchronous `params`, `searchParams`, `cookies()`, or `headers()`.
- **Use `npx next typegen` with `PageProps` and `LayoutProps`** in all TypeScript Next.js projects to eliminate manual prop type boilerplate and catch route parameter mismatches in CI before running a full production build.
- **Refactor synchronous helper functions to `async`** whenever you encounter `@next-codemod-error` or `UnsafeUnwrappedCookies` in shared utility modules.
